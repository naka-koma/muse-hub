# セッションとレビュー

[English](review.md) | 日本語

[開示ポリシー](policy.ja.md) で `arithmetic` への `read` と `consult` を許可します。両方のダミーエージェントに `code: full` を設定してHubを起動します。レビューはHubの中で実行します。

## レビューを始める

次の引数で `discuss` を呼びます。提案役が下書きを作り、レビュー役が確認します。その指摘を提案役が反映します。Hubは情報を渡すたびに受け手のポリシーを確認します。1ジョブあたりの上限は3ラウンドです。

```json
{"agents":["dummy_proposer","dummy_reviewer"],"topic":"2 + 3","context":"","data_category":["code"],"rounds":2,"mode":"review","request_id":"review-1"}
```

`discuss` は `job_id` とHubの `session_id` を返します。`job_id` を `get_result` に渡すと、`review` に結論、合意点、相違点、未決事項、ラウンド数が返ります。DBには最終要約と途中の判定の監査メタデータを保存します。下書きや指摘の本文は保存しません。保存済みの要約も、取得時のポリシーで判定します。

## セッションを再開する

`list_sessions` で最近のセッションと `resumable` を確認できます。続きから実行するには、新しい `request_id` と前回の `session_id` を指定します。前回までに完了したラウンド数を引き継ぎます。エージェント固有のセッションIDはローカルDBの中で管理します。

異なるリビジョンのポリシーを読み込むと、以前のセッションは再開できなくなります。ポリシーを元に戻しても再開できません。一時許可を使ったと記録されたセッションも再開できません。現在、一時許可は無効です。

転送の拒否を試すには、レビュー役の設定を `dummy_reviewer: {code: summary}` に変えてHubを再起動します。新しいレビューでは下書きの転送が拒否され、要約は返りません。
